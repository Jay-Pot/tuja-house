# 팥빵이네 투자하우스 (앱)

설치·서버 없이 열리는 가족 자산 앱. 이 폴더(`app/`) 전체가 깃허브 저장소 하나가 된다.

## 화면
| 탭 | 하는 일 |
|---|---|
| 🏠 홈 | 가족 총자산, 시장 지표, 목표 달성률, 유동성, 자산 배분(종류별·구성원별), 업종 비중, 통화별, 자산 추이, 투입 금액, 예상 배당 |
| 💼 보유 | 구성원별·종목별·계좌별 잔고, 수익률, 정렬. 종목을 누르면 차트·200일선·52주 범위·배당·내 보유·노트 |
| 📝 기록 | 매매일지(잔고 반영 선택, CSV 저장), 현금흐름 |
| ⭐ 관심 | 묶음별 관심 종목. 상세 · 컴팩트 · 차트 보기 |
| 🗺 업종지도 | 업종별 오늘 등락과 내 비중. 칸을 누르면 종목 목록 |
| 🔍 리서치 | 종목·시장·매매 복기 노트, 검색, 문서 보관. **대가 포트폴리오**(대가별 · 겹침 순위 · 분기 변화) |
| 🧪 분석·도구 | 보유 종목 위치(200일선·52주), 매매 시뮬레이션, 물타기 평단, 적립 복리 |
| ⚙️ 가족·설정 | 구성원(나·아내…)과 각자의 증권 계좌·예금·부동산 등, 동기화, 백업·복원·초기화 |

## 내 정보는 어디에 있나
- **이 저장소(공개)에는 자산 내용이 없다.** 앱 코드, 시세를 받을 종목 목록, 받아 둔 시세뿐이다.
- 자산 내용은 앱을 연 기기의 브라우저에 저장된다.
- **동기화**를 켜면 내 깃허브의 *비공개* 저장소 안 `data.json` 한 파일에도 저장되고, 같은 저장소·토큰을 넣은 기기끼리 자동으로 맞춰진다.

## 동기화 준비 (한 번만)
1. 깃허브에서 새 저장소를 **Private** 으로 만든다. 이름 예: `tuja-data` (README 추가에 체크).
2. Settings → Developer settings → Fine-grained tokens → Generate new token.
   Repository access = *Only select repositories* → 그 저장소만. Permissions → **Contents: Read and write**.
3. 앱의 가족·설정 → 기기 간 동기화에 `아이디/tuja-data` 와 토큰을 넣고 연결.
4. 아내 기기·PC에도 같은 저장소 이름과 토큰을 넣는다.

동작: 고치면 몇 초 뒤 올리고, 다른 기기는 화면으로 돌아올 때와 1분마다 받아 온다. 올릴 때 다른 기기가 먼저 올렸으면
받아서 **항목별로 합친 뒤** 다시 올린다(나중에 고친 쪽이 이기고, 지운 것은 지운 채로 남는다). 통째로 덮어쓰지 않는다.

## 처음 잔고 넣기
- 내 컴퓨터에서 `invest/make_app_data.py` 로 만든 `invest/data/app_import_날짜.json` 을 가족·설정 → 가져오기로 불러온다.
- 또는 잔고 CSV(`account,name,qty,value_krw[,cost_krw]`)를 붙여 넣는다. 수량이 빈 줄은 그 계좌의 예수금.
- 한 기기에서만 불러오면 된다. 나머지 기기는 동기화로 따라온다.

## 시세
브라우저에서는 네이버·야후 시세를 직접 부를 수 없다. 그래서 깃허브 Actions(`.github/workflows/prices.yml`)가
평일 장중 15~30분마다 `scripts/fetch-prices.mjs` 를 돌려 `data` 브랜치에 써 두고, 앱은 그 파일만 읽는다.
- `prices.json`: 대표 종목(`data/tickers.json`)의 현재가·등락·60/200일선·52주 고저·최근 1년 배당 + 시장 지표(코스피, S&P 500, 나스닥, 달러/원, 금)
- `all-<시장>.json`: 상장 종목 전체의 이름·코드·현재가·등락. `kr` 국내 · `us` 미국 · `jp` 일본 · `hk` 홍콩 · `cn` 중국 · `vn` 베트남 (약 2만 3천 종목). 종목 찾기와, 대표 종목이 아닌 보유 종목의 시세에 쓴다. 앱은 국내 목록만 먼저 받고 나머지는 종목을 찾기 시작할 때 받는다. 외화 종목은 `prices.json` 의 환율(달러·엔·홍콩달러·위안)로 원화 환산한다
- `h/<코드>.json`: 종목별 일봉 200일(종목 차트를 열 때 그 종목 것만 받는다)
- 일봉·배당은 장 마감 뒤와 수동 실행 때만 새로 받고, 평소에는 현재가만 받는다.
- 어떤 종목이든 찾아서 담을 수 있다(현재가·등락). 차트·200일선·배당까지 보려면 `data/tickers.json` 에 한 줄 추가(국내 `code`+`mkt`, 미국 `symbol`, `sector`).
- 내 컴퓨터에서 미리 볼 때: `node scripts/fetch-prices.mjs --full`
- 저장소에 60일 동안 아무 변화가 없으면 깃허브가 예약 실행을 멈춘다(메일이 온다). Actions 탭에서 다시 켜면 된다.

## 깃허브에 올리기
1. 새 **공개** 저장소를 만든다(무료 계정의 Pages 는 공개 저장소만 된다).
2. 이 폴더의 내용을 그대로 올린다(`.github` 폴더 포함).
3. Settings → Pages → Branch 를 `main` / `(root)` 로 정한다.
4. Actions 탭에서 `prices` 를 한 번 수동 실행(Run workflow)해 `data` 브랜치를 만든다.
5. `https://<아이디>.github.io/<저장소>/` 를 열고, 잔고를 넣고, 동기화를 연결한다. 휴대폰에서는 '홈 화면에 추가'.

## 파일
| 파일 | 역할 |
|---|---|
| `js/store.js` | 저장·불러오기, 두 기기 내용 합치기(`merge`), 가져오기·백업, 시세 읽기 |
| `js/model.js` | 합계 계산(구성원·종류·업종·배당·월별 투입), 자산 추이 기록, 매매 반영 |
| `js/sync.js` | 깃허브 비공개 저장소와 맞추기 |
| `js/views.js` | 화면 여덟 개 |
| `js/app.js` | 버튼·입력·대화상자 |
| `js/charts.js` · `js/ui.js` | 그래프 · 공통 도구 |

## 담은 종목을 차트 대상에 자동으로 넣기 (선택)
기본으로는 대표 종목(`data/tickers.json`)만 차트·200일선·배당이 나온다. 보유·관심에 담은 다른 종목도 자동으로 넣으려면,
앱 저장소의 Settings → Secrets and variables → Actions 에 다음 둘을 넣는다.
- Variables: `DATA_REPO` = `아이디/tuja-data` (동기화 보관함 저장소)
- Secrets: `DATA_TOKEN` = 보관함 토큰
그러면 시세를 받을 때 보관함에서 종목 **이름만** 읽어 그 종목의 일봉도 같이 받는다(한 번에 80개까지).
주의: 이렇게 하면 공개된 `data` 브랜치의 시세 파일에 그 종목 이름이 들어간다(수량·금액은 들어가지 않는다).

## 분석·도구
매매 시뮬 · 미래 가치(미래값 / 필요 월투자금 / 필요 기간 / 필요 수익률) · 리밸런싱(목표 비중은 동기화됨) · 원금회수 · 분할 전략(정액 분할매수 + 과거 검증, 가격 구간별 매수·매도)
· 수익률 비교 · 자산 추이 기록 · 배당 · 종목 위치 · 물타기 · 해외주식 양도세 어림. 계산은 `js/tools.js`.
세금·수익률 계산은 단순 가정이며 실제와 다를 수 있다.

## 그 밖에
- 데모 모드(머리의 🎬): 가상의 가족 자료로 둘러본다. 켜 둔 동안에는 저장도 동기화도 하지 않으므로 실제 자료는 바뀌지 않는다.
- 배당 등록: 분석·도구 → 배당에서 실제로 받은 배당(지급 완료·예정)을 적는다.
- 홈 카드 순서·숨기기, 달러로 보기, 글자 크기, 밝게/어둡게는 기기마다 따로 저장된다.

## 차트
- 대표 종목과 차트 대상에 든 종목: 앱이 직접 그린 차트(200일선 포함).
- 그 밖의 국내 종목: 종목을 열 때 네이버 증권의 차트 그림(1년·3년·일봉·주봉)을 불러온다. 미리 받아 두는 것이 없어서 앱이 무거워지지 않는다.
- 그 밖의 해외 종목: 종목 상세를 열면 "보고 싶은 종목"에 올라가고, 차트 자동 추가(위 DATA_REPO · DATA_TOKEN)를 켜 두었다면 다음 시세 갱신 때 일봉을 받아 온다.

## 문서 (선별노트 등)
리서치 탭의 "문서 올리기"로 HTML·텍스트 파일을 통째로 보관한다. 본문은 이 기기와, 동기화를 켰다면 보관함 저장소의 `docs/<id>.html` 에 들어가고
다른 기기에서는 열 때 받아 온다. 문서는 격리된 틀(sandbox) 안에서 열려서 앱의 저장분에 접근하지 못한다. 같은 제목으로 다시 올리면 새 것으로 바뀐다.

## 대가 포트폴리오
리서치 탭의 «대가 포트폴리오»는 `data/gurus.json` 한 파일을 읽는다. 미국 SEC 13F 공시를 정리한 공개 자료라 누구에게나 같은 내용이고, 내 자산 자료와 섞이지 않는다.
- 보는 방법: 대가별(비중 상위 종목과 직전 분기 대비 증감) · 겹침 순위(두 명 이상이 든 회사) · 분기 변화(신규·확대·축소).
- 종목 상세에도 그 종목을 든 대가와 비중이 한 줄로 나온다.
- «보유»·«관심» 표시는 이 기기 안에서만 계산한다. 공개 파일에는 대가의 자료만 있다.
- 갱신: 분기마다(2·5·8·11월 중순 공시 뒤) `data/gurus.json` 을 새로 올린다. 형식은 `gurus[].top = [티커, 이름, 비중%, 증감]`, 증감은 `null`(변화 없음) · `"new"`(신규) · 숫자(주식 수 증감 %).
- 한계: 미국 상장 주식의 매수 포지션만 나온다. 분기가 끝난 뒤 최대 45일 늦다. 전부 판 종목은 표에 없다.

## 선별 노트 (공개판)
`notes/` 폴더에 숫자만으로 채점한 종목 선별 노트를 둔다. 보유 종목·잔고는 싣지 않는다. 보유 표시가 있는 원본은 리서치 탭의 «문서»에 올려 비공개로 본다.
